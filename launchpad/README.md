# LaunchPad

Внутренний трекер продюсерского центра образовательных продуктов: здесь ведутся проекты (какие курсы ищем, берём в работу, запускаем), у каждого проекта — свои запуски (потоки), у запуска — задачи на команду, а к задачам можно оставлять комментарии, чтобы не терять переписку. По сути, это упрощённая внутренняя CRM продюсера, без платёжек и маркетинга, только сама механика ведения проекта от идеи до запуска.

## Команда и роли

Нас двое, поэтому роли из методички объединили по смыслу: один человек закрывает всё, что касается данных, второй — всё, что касается выдачи наружу.

| Роль | Отвечает за | Файлы | Кто |
|---|---|---|---|
| Архитектор данных + Бэкендер А | схема таблиц, связи, SQL-запросы, работа с базой | `schema.sql`, `seed.sql`, `store.go`, `model.go` | Родион Берсенев |
| Бэкендер Б + Интегратор | хендлеры, коды ответов, валидация, контракт API, фронт | `handlers.go`, `main.go`, `README.md`, вёрстка | Сергей Охотников |

Сборщик — Родион, у него лежит основной репозиторий.

## Схема данных

Пять таблиц, одна сущность с явным статусом почти в каждой — так и есть смысл трекера. Полностью — в [schema.sql](schema.sql).

- **users** — сотрудники центра (продюсер, маркетолог, методист, руководитель).
- **projects** — образовательные продукты, которые центр ищет или ведёт. У каждого проекта есть владелец из `users` и статус: `search → in_progress → launched`, либо `archived` / `cancelled` в сторону.
- **launches** — запуски (потоки) конкретного проекта, у проекта их может быть несколько подряд. Статус: `planned → running → finished`, либо `cancelled`.
- **tasks** — задачи внутри запуска, с исполнителем из `users` и статусом `todo / in_progress / done`.
- **comments** — комментарии к задаче, от лица конкретного пользователя.

Связи все «один ко многим»: пользователь → много проектов (как владелец), проект → много запусков, запуск → много задач, пользователь → много задач (как исполнитель), задача → много комментариев. На все внешние ключи стоят индексы, статусы зафиксированы через `CHECK`, чтобы в базу не прилетело что попало.

## API

| Метод | Путь | Тело запроса | Успех | Ошибки |
|---|---|---|---|---|
| GET | /health | — | 200, `{"status":"ok"}` | — |
| GET | /users | — | 200, массив | 500 |
| GET | /users/{id} | — | 200, объект | 400, 404 |
| POST | /users | `{"name":"...","email":"...","role":"producer"}` | 201, объект | 400, 422 |
| PATCH | /users/{id} | `{"name":"...","role":"lead"}` | 200, объект | 400, 404, 422 |
| DELETE | /users/{id} | — | 204 | 400, 404 |
| GET | /projects?status= | — | 200, массив | 500 |
| GET | /projects/{id} | — | 200, объект | 400, 404 |
| POST | /projects | `{"title":"...","description":"...","owner_id":1,"budget":150000}` | 201, объект | 400, 422 |
| PATCH | /projects/{id} | `{"status":"in_progress"}` | 200, объект | 400, 404, 422 |
| DELETE | /projects/{id} | — | 204 | 400, 404 |
| GET | /launches?project_id= | — | 200, массив | 400, 500 |
| GET | /launches/{id} | — | 200, объект | 400, 404 |
| POST | /launches | `{"project_id":1,"title":"...","start_date":"2026-10-01"}` | 201, объект | 400, 422 |
| PATCH | /launches/{id} | `{"status":"running"}` | 200, объект | 400, 404, 422 |
| DELETE | /launches/{id} | — | 204 | 400, 404 |
| GET | /tasks?launch_id=&assignee_id= | — | 200, массив | 400, 500 |
| GET | /tasks/{id} | — | 200, объект | 400, 404 |
| POST | /tasks | `{"launch_id":1,"title":"...","assignee_id":2,"due_date":"2026-10-05"}` | 201, объект | 400, 422 |
| PATCH | /tasks/{id} | `{"status":"done"}` | 200, объект | 400, 404, 422 |
| DELETE | /tasks/{id} | — | 204 | 400, 404 |
| GET | /comments?task_id= | — | 200, массив | 400, 500 |

У комментариев нет `PATCH` и нет `GET /comments/{id}` — это просто лог переписки по задаче, редактировать чужие реплики задним числом мы не даём, только оставить новую или удалить свою по ошибке.

## Как запустить

```bash
# поднять базу
docker compose up -d

# подтянуть зависимости (нужен интернет один раз, дальше всё из кэша)
go mod tidy

# запустить сервер
DATABASE_URL="postgres://app:secret@localhost:5432/app?sslmode=disable" go run .

# проверить
curl http://localhost:8080/health
```

Adminer для просмотра базы глазами — на `http://localhost:8081` (сервер `db`, логин `app`, пароль `secret`, база `app`).

Тестовые данные накатываются сами при первом старте базы — 4 пользователя, 3 проекта, 3 запуска, 4 задачи, 3 комментария (см. [seed.sql](seed.sql)). Если база уже поднималась раньше и `seed.sql` поменялся, накатить его руками:

```bash
docker exec -i launchpad-db-1 psql -U app -d app < seed.sql
```

### Фронт

Лежит в [front/](front/), открывается прямо файлом в браузере — сервер статику не раздаёт, `app.js` ходит на `http://localhost:8080` напрямую через `fetch()` (CORS на сервере уже открыт). Показывает список проектов, форму создания и удаление, ошибки сервера выводятся в баннер сверху, а не молчат.

```bash
open front/index.html
```

Сервер (`go run .`) и база (`docker compose up -d`) должны быть подняты заранее.

## Что сделано

- **Схема БД** — 5 таблиц, связи, индексы на FK, статусы через `CHECK`.
- **Контракт API** — все эндпоинты из таблицы выше реально работают.
- **CRUD** — `store.go`/`model.go`/`handlers.go`: SQL только через `$1`, валидация входных данных до похода в базу, ошибки Postgres (уникальность, внешние ключи) превращаются в 422, а не текут наружу как есть.
- **Фронт** — список/создание/удаление проектов через `fetch()`, ошибки на экране.
- **Тестовые данные** — `seed.sql` накатывается при старте контейнера.
